# Телефонный сервис

Сервис для хранения абонентов, управления активными звонками и их историей.
У звонка есть участники, состояние, длительность и периоды подключения участников.
Один звонок может объединять нескольких абонентов

## Стек

- Go для бэкенда
- PostgreSQL для хранения абонентов и звонков
- OpenAPI и ogen для описания API и генерации серверного кода
- pgx и sqlc для подключения к БД и типизированных SQL запросов
- Goose для миграций
- Koanf для загрузки конфигурации
- Docker Compose для запуска приложения и БД
- OpenTelemetry и Prometheus для логов и метрик и трассировки

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/calls` | Список звонков; необязательный фильтр `status=active` или `status=finished` |
| `GET` | `/calls/{id}` | Звонок с участниками и периодами подключения |
| `POST` | `/calls/start` | Начать звонок |
| `POST` | `/calls/{id}/connect` | Подключить абонента |
| `POST` | `/calls/{id}/disconnect` | Отключить абонента |
| `POST` | `/calls/{id}/finish` | Завершить звонок |
| `GET` | `/abonets` | Список абонентов |
| `GET` | `/abonets/{id}` | Данные абонента |
| `GET` | `/abonets/{id}/calls` | Все звонки абонента, включая активные |
| `GET` | `/abonets/{id}/stats` | Количество, общая и средняя длительность завершённых звонков |

Путь `/abonets` сохранён для совместимости. Старый `POST /call` заменён на
`POST /calls/start`: передавать `duration` и `created_at` больше не нужно.

### Начало звонка

Запрос содержит `participants` с полями `name` и `phone_number`.
Успешный ответ имеет код `201`, остальные операции возвращают `200`.

- Нужен хотя бы один участник; начальные участники сразу подключены.
- Телефоны участников не должны повторяться независимо от форматирования.
- Отсутствующие абоненты создаются, данные существующих не изменяются.
- Абоненты, звонок, связи и периоды подключения сохраняются одной транзакцией.
- ID назначает БД. Серверное время берётся из PostgreSQL.

### Управление звонком

`connect` и `disconnect` принимают `{"subscriber_id": 42}`; `finish` — без тела.
Подключать можно существующих абонентов только к активному звонку.

- Состояния звонка: `active` и `finished`.
- Для активного звонка длительность вычисляется на момент чтения.
- `finish` фиксирует длительность и закрывает все открытые периоды участия.
- Выход последнего участника автоматически завершает звонок.
- Повторный `finish` возвращает прежний результат без изменения времени.
- Повторное подключение после выхода создаёт новый период участия.
- `participants` содержит всех участвовавших абонентов, `participations` — периоды
  участия. Отсутствие `left_at` означает, что участник подключён.
- Для новых времён используется RFC 3339 в UTC; формат `created_at` сохранён.
- Старые звонки считаются завершёнными, неизвестные времена не восстанавливаются.
- Неизвестный объект возвращает `404`, неверные параметры — `400`, конфликт
  состояния — `409`. Уже подключённого участника нельзя подключить повторно;
  уже отключённого нельзя отключить повторно.
- Параллельные изменения защищены версией звонка и транзакцией. При конфликте
  версии сервис перечитывает состояние и повторяет операцию до трёх попыток.
- Статистика считается по полной длительности завершённых звонков, не по сумме
  периодов участия. При отсутствии завершённых звонков возвращаются нули.

## Архитектура

### Ответственность слоёв

- Хендлер принимает HTTP запрос и формирует ответ
- Юзкейс управляет конкретным сценарием
- Сервис содержит общие бизнес-правила
- Репозиторий читает и сохраняет данные

Вызовы идут от хендлера через юзкейс и сервис к репозиторию
Слои не вызывают соседние компоненты и верхние уровни

## Тесты

`make test` запускает тесты без Docker. Существующие unit-тесты используют
сгенерированные Uber GoMock моки; обновление — `make mocks_gen`.

`make test-integration` запускает 10 happy-path сценариев HTTP API с проверкой
гонок. Нужны Go из `go.mod`, работающий Docker и доступ к образам Docker Hub
при первом запуске. Окружение создаётся автоматически через testcontainers:
PostgreSQL `18.6`, реальные Goose-миграции и отдельная БД на каждый тест.
Локальные `configs/.env` и Docker Compose не используются.

Интеграционные тесты находятся в `internal/tests/cases` и включаются тегом
`integration`. Общий `AcceptanceSuite` использует `httptest.NewTestServer`
из Go 1.27 и ogen-клиент с транспортом `server.Client()`. Два доменных сьюта
работают параллельно, сценарии внутри каждого выполняются последовательно.
Серверы, соединения, тестовые БД и контейнер освобождаются после выполнения.

Чистые билдеры находятся в `internal/tests/builders`, переиспользуемая фикстура
агрегата звонка — в `internal/tests/fixtures`. Опции билдеров меняют поля моделей,
опции фикстуры задают участников и периоды участия из готовых моделей.

GitHub Actions запускает интеграционные тесты на pull request, push в `master`
и вручную. При падении лог сохраняется как артефакт `integration-logs`.
